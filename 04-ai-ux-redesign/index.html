What should a screen show you when the AI is confidently wrong?

An agent just ran against your real business data, and a purchase order is about to go out. Three of four line items are right. On the fourth it wrote a fluent, specific, completely false sentence about a supplier’s lead time.

001/ The problem

A run that crashes is easy.

The interesting failure looks exactly like a success. Nothing in the model’s output marks the false sentence as different from the correct ones around it — same fluency, same specificity, same tone of certainty.

The run wrote

“Volcán Dark ships from Cooperativa Tolima in 14 days, so the 120 kg lands before you run dry on day 17.”

The run wrotelead_time_days = 14
The record sayslead_time_days = 28

The supplier record the run itself read says 28. The model was not hedging. There is no signal inside its output that separates this sentence from the three true ones — which is why asking the model how confident it feels cannot be the answer.

002/ The design

Five problems, five answers.

Each one is a decision the screen has to make out loud. The prototype implements all five, live — nothing on it is a screenshot.

01

Streaming

The wait is filled with a commitment, not a spinner. The agent publishes its plan before the first tool call, and the plan’s last line is the limit of its own authority.

02

Confidence

No uncalibrated “87% sure” badge. Every value is verified, derived or assumed — and only assumed gets colour.

03

Tool transparency

One line per call, with the real payload one click away. Legibility at a glance, full evidence on demand.

04

Graceful failure

The model is never asked to grade itself. A deterministic check re-reads the record and shows both values side by side.

05

Human-in-the-loop

The pause goes before the irreversible step. Partial approval, editing with the original kept, and an expiry that defaults to not sending.

004/ The decision

Three ways to show doubt.

One question, asked of each: does it give the operator a reason to catch the false lead time?

Discarded

Confidence score

  • —Uncalibrated: the model has no reliable access to its own reliability
  • —Message-level, so three solid facts dilute one invention
  • —Unactionable: nobody knows what to do at 87 versus 62

Verdict — the false claim sits inside the 87%

Discarded

Persistent disclaimer

  • —Identical on a perfect run and on a broken one
  • —On every screen, therefore read on none
  • —Transfers responsibility without naming one thing to check

Verdict — a constant warning carries no information

Shipped

Provenance per claim

  • +Uncertainty attaches to the claim, never to the message
  • +Verified, derived or assumed — only the last gets colour
  • +A deterministic check re-reads the record the run read

Verdict — flagged, and the clean items stay clean

005/ Honest limits

What this is not.

The parts a case study usually leaves out, stated before you have to ask.

01/ Was any of this usability tested?

No. No usability testing was run on this design. There are no task-time or error-rate numbers anywhere in it, because none were measured — the case study argues from design reasoning and states what it would test first.

02/ Is this real client work?

No. It is unsolicited, unaffiliated and uncommissioned — a speculative concept, never presented as client or paid work. It uses no company’s logo, brand or product assets.

03/ Is the data real?

No. The brand, suppliers, SKUs, quantities, order references and the approver are all invented for the prototype. No real business data appears anywhere in it.

04/ What would it cost to build?

Provenance has to be plumbed. The runtime must tag every output field with the tool result it came from, which is real engineering and assumes structured output. That price is exactly why teams ship a percentage badge instead — and it is the whole difference.

05/ What would you test first?

Whether an operator under time pressure actually reads the contradiction card before approving, or clears the gate on muscle memory. The design assumes the pause is load-bearing; that assumption is the one most worth breaking.
